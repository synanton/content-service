# Synanton Go Project Conventions

Keep every Synanton Go service (content-service, equalix-go) recognizable as family: same docs skeleton, same contribution bar, same evidence discipline.

**Core areas:** README structure (badges, Status + maturity table, What It Is, architecture, quick start, API, config reference, observability, development, roadmap), `CONTRIBUTING.md` gates, `docs/IMPLEMENTATION.md` phased plans, code-pinned runbooks, keep-a-changelog + `VERSION` source of truth, conventional commits, explicit staging, `CNT-`/`EQLX-` branch prefixes, manual merges.

**Before applying changes:** Read the reference for the exact templates, gates, and anti-patterns.
